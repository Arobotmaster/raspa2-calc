# RASPA 高通量计算模式使用说明

## 概述

高通量计算模式用于**批量处理大量框架结构**，基于 CSV 列表自动生成 `mc*` 任务目录，并通过高通量调度提交作业。支持 RASPA2 / RASPA3 双版本，可配合 `raspa-scale` 动态扩缩容。

## 特点

✅ **批量框架处理** - 从 CSV 读取框架列表，一键生成任务
✅ **自动 UnitCells** - 根据截断半径自动计算
✅ **孔隙率可选来源** - 从 CSV 读取（推荐），未提供时使用默认值
✅ **RASPA2/RASPA3 双版本** - 自动/手动切换，模板统一管理
✅ **RASPA3 资源复制** - 自动复制 `force_field.json` 与分子 JSON，并按 CIF/组分筛选
✅ **高通量调度** - 统一走高通量 submit 脚本，支持 `raspa-scale` 扩缩容
✅ **配置快照** - 在输出目录保存 `.raspa_config.yaml`，便于恢复与补交
✅ **pyMSER 自动平衡** - 可选启用自动平衡与续跑

## 两个核心问题的实现

### 1. 框架名获取 ✅
**从 CSV 文件读取** - 与参数筛选模式一致

通过配置文件指定:
```yaml
calculation:
  csv_file_path: "/path/to/structures.csv"
  framework_column: "coreid"  # 或列名 / 列序号
```

### 2. 孔隙率获取 ✅
**优先从 CSV 读取（推荐）**

通过配置文件指定:
```yaml
calculation:
  use_void_csv: true
  void_csv_file: "/path/to/void_data.csv"
  void_column: "VF"
```

- `use_void_csv: true` → 按框架名匹配孔隙率
- 未启用或未匹配时 → **HeliumVoidFraction 默认写入 0.5**（会覆盖模板中的值）

## 完整配置示例

### config.yaml

```yaml
# 环境配置
environment:
  work_dir: "/path/to/work"
  raspa_version: "raspa2"  # 或 "raspa3"

  # RASPA2
  raspa_dir: "/path/to/raspa2"
  raspa2_cif_dir: "/path/to/cif"
  template_path: "/path/to/simulation.input"

  # RASPA3
  raspa3_conda_env: "raspa3"
  raspa3_cif_base_path: "/path/to/cif"
  raspa3_template_path: "/path/to/simulation.json"
  raspa3_json_dir: "/path/to/raspa3json"

# 高通量计算参数
calculation:
  csv_file_path: "/path/to/structures.csv"
  framework_column: "coreid"
  output_directory: "ht_output"

  cutoff_radius: 12.8
  default_molecules: "CO2"   # 多组分用空格分隔，如 "CO2 CH4"

  use_void_csv: true
  void_csv_file: "/path/to/structures.csv"
  void_column: "VF"

  # CIF 参数缓存（可选，加速重复运行）
  use_cif_cache: true
  cif_cache_path: "/path/to/params_cache.json"

  # pyMSER 自动平衡（可选）
  mser:
    enable: true
    target_cycles: 1000
    add_cycles: 300
    max_iter: 20
    uncertainty: "uSD"
    conda_env: "pymser"
    llm: true
    batch_size: 5

  # 节点优先级（可选）
  node_priorities:
    master-node: 2
    worker-node-01: 1

# 日志配置
logging:
  output_dir: "1log"
  enable_job_logs: true
```

## pyMSER 自动平衡（高通量）

- 使用 `calculation.mser` 配置
- 启用后 worker 会在模拟完成后自动调用 `raspa_calc.domain.algorithms.auto_mser_raspa2` / `raspa_calc.domain.algorithms.auto_mser_raspa3` 判定平衡并续跑
- 平衡截断点使用 pyMSER 的 `t0`（默认判据）
- 生成的 simulation.input / simulation.json 会自动写入适配 pyMSER 的循环与输出配置

示例（高通量开启 pyMSER）：
```yaml
calculation:
  mser:
    enable: true
    target_cycles: 2000
    add_cycles: 400
    max_iter: 20
    uncertainty: uSD
    conda_env: pymser
```

## 使用方法

1. **编辑配置文件** `/path/to/raspa2-calc/.raspa_tools/config.yaml`
2. **运行命令**:
   ```bash
   raspa-calc  # 选择模式 2
   ```
   或直接运行：
   ```bash
   python -m raspa_calc.entrypoints.task_runner
   # 指定 CSV + 列名/列号：
   python -m raspa_calc.entrypoints.task_runner /path/to/structures.csv coreid
   python -m raspa_calc.entrypoints.task_runner /path/to/structures.csv 1
   ```
3. **提交后管理并发**:
   ```bash
   raspa-scale status <output_directory>
   raspa-scale 200 <output_directory>   # 动态调整 worker 数
   ```

## 交互流程（核心步骤）

执行顺序如下（提示语略有精简）：

1. 初始化设置（RASPA 版本）
2. 处理 CSV（读取框架列表）
3. CIF 检查 + 标签清理提示（如检测到编号标签）
4. 配置摘要 + simulation 示例预览
5. 处理结构文件（并行）
6. 更新配置并输出总结
7. 提交任务

如需完整提交日志，可设置：
```bash
export RASPA_SUBMIT_VERBOSE=1
```
如需控制简略提示频率，可设置：
```bash
export RASPA_SUBMIT_LOG_EVERY=10
```
如需输出更完整的结构处理日志，可设置：
```bash
export RASPA_HT_VERBOSE=1
```

## 输出目录结构

```
ht_output/
├── .raspa_queue/
│   ├── next_id
│   ├── last_id
│   ├── next.lock
│   └── retry.list
├── .raspa_worker_limit
├── .raspa_jobs.list
├── 1log/                 # 可选: 作业日志目录
├── mc1/
│   ├── simulation.input  # 或 simulation.json
│   ├── raspa_calculation.log
│   └── Output/ or output/
```

说明：
- `mcX__running` / `mcX__done` / `mcX__failed` 由 worker 自动重命名
- `.raspa_queue/` 为共享队列目录，支持多 worker 并发抢任务

## 验证结果

检查生成的 simulation.input / simulation.json：

```bash
cat ht_output/mc1/simulation.input
```

应看到:
- `FrameworkName <MOF>`
- `UnitCells X Y Z`
- `HeliumVoidFraction <value>`
- `Component 0 MoleculeName ...` (多组分按顺序写入)

RASPA3（simulation.json）则应看到:
- `Systems[0].Name` 指向 CIF
- `Systems[0].NumberOfUnitCells`
- `Systems[0].HeliumVoidFraction`
- `Components[*].Name` 被写入分子名

## 参数说明

### cutoff_radius
- 截断半径（Å），用于自动计算 UnitCells

### default_molecules
- 分子名称，支持空格分隔的多组分

### use_void_csv / void_csv_file / void_column
- 是否从 CSV 读取孔隙率；未启用时默认 0.5

### output_directory
- 输出目录名（在 `work_dir` 下创建）

### template_path / raspa3_template_path
- RASPA2 必须提供 `simulation.input` 模板
- RASPA3 可提供 `simulation.json` 模板，不提供则使用内置模板

### raspa3_json_dir
- RASPA3 力场与分子 JSON 目录，会按 CIF / 分子名筛选并复制

### use_cif_cache / cif_cache_path
- 启用 CIF 参数缓存，避免重复计算 UnitCells/孔隙率

### node_priorities
- 控制节点优先级，值越大越优先

### logging.output_dir / enable_job_logs
- 控制作业 .out/.err 输出位置与开关

## 常见问题

**Q: RASPA2 模板必须设置吗？**
A: 是。高通量模式会修改模板并复制到任务目录，未设置会直接失败。

**Q: CSV 中缺失 CIF 会怎样？**
A: 缺失的框架会被自动跳过，并在总结中提示。

**Q: 为什么 HeliumVoidFraction 都是 0.5？**
A: 未启用 `use_void_csv` 时会写入默认值 0.5，请在 CSV 中提供孔隙率并启用该选项。

**Q: 任务提交后没跑？**
A: 先运行 `raspa-status` 查看，再用 `raspa-scale` 扩容/补交。

## 注意事项

1. **配置文件同步**：确保 `/path/to/raspa2-calc/.raspa_tools/config.yaml` 与实际运行路径一致
2. **CSV 列名**：`framework_column` / `void_column` 必须与 CSV 列名完全一致
3. **CIF 路径**：RASPA3 使用 `raspa3_cif_base_path`，RASPA2 使用 `raspa2_cif_dir`
4. **RASPA3 依赖**：确保 `raspa3_conda_env` 可激活，且 `raspa3_json_dir` 中包含 `force_field.json` 和分子 JSON
5. **集群环境**：多节点提交必须在 NFS 共享目录下进行
